# Feedback and improvement

Every observation records target, reason, viewing context and requested scope: `page`,
`project`, `series` or `library`. A library suggestion remains a suggestion. Confirmed choices
retain wording/scope in `decisions`; supersede explicitly while preserving earlier records.
Do not infer a future default from a single compliment.

Contexts: `screen_review`, `native_powerpoint`, `live_projection`, `teaching_use`, `unspecified`.
Record reporter and observation, with artifact hash when known. User-reported use is distinct
from the agent's direct inspection.

Reference lifecycle:
- `reference`: inspiration with provenance and limitations.
- `tried`: adapted in a concrete project, with linked artifact/checks.
- `reusable`: reviewed adaptation, clear use case and evidence supporting reuse.
- `retired`: retained provenance, no longer recommended.

Lifecycle and evidence are separate. Record source/XML, renderer, native PowerPoint, projection
and teaching feedback independently. No status implies all checks happened. Promotion is a
deliberate maintainer edit with linked evidence and reason, never a side effect of feedback import.

After use, save worthwhile observations and classify the action: this artifact, series choice,
reference improvement or recurring tool defect. Make the smallest useful change and keep
unaffected approved wording. For defaults/tools, exercise relevant representative cases and
different content shapes when available. Check behavior/output, not prose matching a regex.
Update source, catalog, version, gallery and installation deliberately.

Do not accumulate a global restriction for every isolated glitch. Keep focused private issue
records with the source/output and resolution. Periodically merge duplicate patterns and
narrow overbroad advice. Correct a renderer defect primarily in its implementation or a
tool-specific note; let teaching feedback inform design choices.

Use the [resolution operation](operations.md) to record applied, declined or deferred feedback,
retaining observations and history. Applied items link their resulting output hash. The gallery
records the selected example, optional registered output and whether an issue affects current
delivery. Deferred delivery-blocking feedback remains unresolved.
